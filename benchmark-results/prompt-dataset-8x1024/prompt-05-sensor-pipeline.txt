某工厂准备把六个月的设备传感器记录接入一个实时异常检测系统。数据来自温度、振动、电流、压力和声学通道，采样频率从每秒一次到每秒八千次不等。边缘网关先把数据编码成带时间戳的 parquet chunk，再通过专线发送到中心集群。生产线上有三种设备固件版本，其中旧版本会把传感器校准值写入本地配置，而新版本把校准值作为每条记录的 metadata 发送。分析模型需要同时读取原始窗口、校准参数、维护历史和工艺配方。

一次异常发生在 03:17:42。第七号压缩机的振动 RMS 在 11 秒内从 0.8 g 上升到 3.4 g，温度只上升了 2.1 摄氏度，电流没有明显变化。边缘端告警延迟为 180 ms，但中心模型在收到完整窗口后才把告警等级从 warning 提高到 critical。事后检查发现，中间的 parquet chunk 按设备时间排序，而模型的读取请求按特征类型聚合，导致同一个窗口的列分散在许多小对象中。page cache 对顺序扫描有效，却不能完全掩盖这种列级随机访问。

数据工程师设计了两级缓存。第一层是每个 worker 的 pinned ring buffer，用于把即将送入 GPU 的张量转成连续布局；第二层是共享 DRAM cache，保存最近几分钟的原始 chunk 和经常使用的校准表。缓存条目带有设备 id、固件版本、窗口起止时间和 schema hash。任何固件升级都会使旧 schema 的条目失效，不能只依赖文件名判断兼容性。若 ring buffer 满了，系统应该产生 backpressure，而不是覆盖一个仍被 CUDA stream 使用的地址。

训练和推理的访问模式并不相同。训练任务会顺序读取数百个设备的整天数据，适合大块预取和较大的 read-ahead；在线推理只读取一个设备最近几十秒的窗口，访问碎片更小。把训练和在线任务放在同一台机器上会造成 page cache 抖动。实验需要分别记录文件系统 read、物理块设备 read、DRAM bandwidth、GPU H2D bandwidth 和队列等待，并用相同的设备窗口重放请求，避免把传感器噪声误认为系统性能变化。

异常检测团队还要求保留可解释性证据。每个告警要引用触发它的传感器通道、窗口内最大梯度、与历史基线的偏差，以及使用的模型版本。缓存优化不能改变记录顺序或浮点缩放；如果同一个窗口在 pageable 和 pinned 路径下产生不同的 logits，必须先停止性能比较。为了避免时间戳时区错误，所有 manifest 使用 UTC，边缘端本地时间只作为显示字段。

容量估算表明，单个设备的高频声学通道一天可以产生 300 GiB 数据。完整保留不可能放在 host cache 中，因此缓存策略必须优先保存最近异常窗口、校准表和下一批即将到达的窗口。一个简单的 LRU 可能把高频但低价值的正常噪声留在内存，驱逐掉真正有用的异常上下文。候选策略包括按设备分片的 LRU、按异常分数加权的 LFU，以及由调度器根据下一次窗口边界进行预取。每种策略都应报告命中率、淘汰字节、预取浪费字节和告警端到端延迟。

项目验收不仅看平均吞吐。测试集要覆盖平稳运行、固件切换、突发异常、网络短断和回放速度变化。每个场景使用独立的自然上下文，模式之间严格配对；三次重复用于估计同一场景的运行噪声，不把三个不同场景混成一个“重复”。最终报告要说明缓存是减少了磁盘访问、减少了 host copy，还是只是改变了 GPU slot 的替换顺序。
传感器项目还要处理采样率变化。固件在低负载时会把振动通道降到 1 kHz，在维护模式下恢复到 8 kHz；如果缓存 key 只包含设备和时间窗口，两个不同采样率的 chunk 可能被错误拼接。正确的 key 至少包含 sampling rate、calibration revision、channel mask 和 compression codec。模型输入还要保存缺失值 mask，因为插值后的零值不能与真正的零振动混淆。

回放工具将把异常窗口、正常窗口和固件切换窗口随机交错，但每次实验使用相同的随机种子和事件顺序。这样可以比较缓存淘汰顺序，而不是比较不同输入顺序。每个窗口结束时记录 ready chunk、source tier、预取浪费和 GPU H2D bytes；如果预取的窗口在被使用前已失效，应计入 wasted prefetch，而不能算作命中。

安全审计还要求缓存数据有明确的生命周期。超过保留期限的原始窗口必须被擦除，派生特征只能保留不可逆 subject key。profile 文件应避免保存原始音频和完整 metadata，只保存 hash、size 和计时字段。性能和隐私检查都通过后，异常检测服务才可以把 host cache 从实验环境迁移到生产节点。
工程师还会对窗口做质量门控：缺少校准参数、时间戳逆序或采样率不匹配的窗口先进入 quarantine queue，不得直接填充共享 cache。门控结果要单独记录 rejected bytes、重试次数和最终告警延迟。这样在比较缓存策略时，任何模式都处理同一批有效窗口，不会因为某条路径更早发现格式错误而得到虚假的速度优势。
